一、软件概况
transmissionbtm（HarmonyOS BitTorrent 客户端软件）（以下简称“本软件”）是一款运行于 HarmonyOS 的 BitTorrent 下载客户端。本软件以开源项目 Transmission 的 libtransmission 引擎（版本 4.1.0 stable，遵循 GPL-2.0 协议）为核心传输能力，通过 N-API 桥接层将底层 C/C++ 引擎能力映射为 ArkTS 可调用的接口，应用界面与业务逻辑层使用 ArkTS + ArkUI（HarmonyOS 声明式 UI 框架）从零编写。
软件坚持“本地运行、最小收集”的设计原则：不注册登录、不内置任何种子、tracker 或搜索索引，不含任何侵权资源，不对用户上传或下载的数据做任何形式的上报与留存，仅作为中立的点对点（P2P）传输工具使用。

二、运行环境
1. 操作系统：HarmonyOS 6.1.1 及以上版本（API 24）。
2. 硬件平台：支持 HarmonyOS 的智能手机（phone）、平板（tablet）及 2in1（PC）设备。
3. 网络：需联网（WiFi 或移动数据）以进行 BitTorrent 对等传输；软件同时提供“仅允许特定 WiFi 条件下传输”的门控策略。
4. 外部依赖：软件包内随附经交叉编译的解译第三方库，包括 libtransmission（4.1.0）、OpenSSL（3.0.15）、libcurl（8.5.0）、libevent（2.1.12）以及 dht、b64、miniupnpc、natpmp、utp、psl 等子依赖库，均为静态链接，随软件一同分发。

三、主要功能
本软件围绕“添加 → 控制 → 查看 → 管理”一条完整的下载链路提供以下功能：
1. 多方式添加下载任务：支持通过磁力链接（magnet:）、.torrent 种子文件、以及 HTTP/HTTPS 直接下载地址三种方式创建任务。
2. 完整的传输控制：对每个下载任务提供开始下载、暂停、继续、删除、移动存储位置等操作，支持按任务设置下载目录。
3. 实时状态统计：每隔 5 秒自动刷新并展示每个任务的关键指标，包括下载速度、上传速度、完成百分比、剩余时间、文件大小、种子数与节点数、分享率等。
4. 文件树管理：以目录层级展示任务内包含的所有文件，支持勾选以决定优先下载或排除部分文件，支持对单个文件设置下载优先级，直观查看每个文件的大小与下载进度。
5. 网络策略配置：支持 HTTP/HTTPS 代理（可选认证），支持“仅 WiFi 传输”开关及 SSID 白名单设置，内置连接状态监控，对网络切换做出响应。
6. 后台持续下载：通过前台服务与 WakeLock 机制，切换到后台后仍可持续进行传输，避免被系统回收。
7. 目录选择与导出：添加种子时可选择保存目录；下载完成后支持将文件导出或复制到本地存储。
8. 多页面架构：界面由下载页、设置页、代理页、关于页、添加任务页、文件树页等组成，交互直观。

本软件采用三层架构设计：
（1）应用层（ArkTS / ArkUI）：负责界面渲染、用户交互、状态管理与业务编排，所有界面文件置于工程的 ETS 目录下，按功能组织为页面（pages）、组件（components）、领域模型（models）、服务（services）等模块。
（2）N-API 桥接层（C++）：将底层引擎能力封装为约 40 个 N-API 方法，向 ArkTS 暴露统一的、同步/异步结合的调用接口；并使用 ThreadSafeFunction 机制将引擎侧事件（如种子状态变化、下载进度更新）回调到 ArkTS 主线程，从而驱动界面刷新。
（3）引擎层（C/C++）：集成 libtransmission 及其依赖库，完成磁力/种子解析、节点发现、对等节点连接、数据分块校验与磁盘写入等实际传输工作。

4.2 关键技术点
（1）N-API 边界安全：所有原生调用统一经由单例桥接类（NativeBridge）完成，避免组件直接散落调用原生方法；对参数与返回类型做严格校验。
（2）线程模型：耗时的原生操作（如添加种子、移动存储位置）通过 taskpool 任务池分发，避免阻塞 UI 线程；引擎回调经 ThreadSafeFunction 切回主线程，保证 UI 更新线程安全。
（3）状态管理：使用 ArkUI 的响应式状态机制（如 @State、@Prop、@Link、@ObjectLink）管理界面数据，实时统计值由轮询与事件驱动相结合进行刷新。
（4）外部输入校验：对用户粘贴的磁力链接、选择的种子文件路径、配置的代理地址等，在进入原生调用前先做格式与安全性校验（如路径穿越、端口范围），防止异常输入导致错误或越权。

五、界面说明与操作步骤
5.1 主界面（下载页）
启动应用后默认进入“下载”页，以卡片列表形式展示所有下载任务。每张任务卡片包含：任务名称、文件总大小、进度条与完成百分比、下载/上传速度、剩余时间（下载中）或分享率（做种中）、状态徽标（下载中 / 已暂停 / 已完成）。下载中卡片每 5 秒自动更新速度和进度。
对卡片执行长按或点击“更多”可弹出操作菜单，包括：开始/继续、暂停、显示文件（进入文件树页）、移动存储位置、删除任务（含确认提示）。

5.2 添加任务页
点击主界面右下角或顶部的“+”/“添加”按钮进入添加任务页，提供三种添加方式：
（1）磁力链接：粘贴以 magnet: 开头的链接，系统解析后创建任务。
（2）.torrent 文件：通过文件选择器选择本机存储的种子文件。
（3）URL 直接下载：输入 HTTP/HTTPS 直链地址。
添加前可通过“下载目录”选择器指定保存位置。点击“添加”后，任务即刻出现在下载页列表，并开始连接节点与拉取数据。

5.3 文件树页
从任务操作菜单选择“显示文件”进入文件树页，按目录层级展示任务内所有文件。每个文件显示文件名称、大小与下载进度。用户可勾选文件以决定是否优先下载或排除（跳过）某些文件；对单个文件可设置下载优先级。通过层级折叠/展开可查看深层目录。

5.4 设置页
设置页集中管理应用运行参数，包括：
（1）上传与下载速度限制；
（2）最大同时活跃任务数；

六、下载业务流程图
1. 用户添加任务（磁力/种子/直链）后，软件将解析出的元信息交给引擎；
2. 引擎向 DHT 网络与各 tracker 公告节点，获取对等节点列表；
3. 软件与可连接的对等节点建立连接，协商并交换数据块；
4. 每个数据块经 SHA-1 校验后写入用户指定目录；
5. 界面每秒（或 5 秒）刷新进度、速度与节点状态；
6. 全部文件校验完成后任务进入“已完成/做种”状态，可继续对外提供上传或保存退出。

七、网络与安全
本软件自身不运营任何服务器，不对等传输由用户设备与对等节点点对点直连完成，传输数据不经过本软件提供方。软件默认仅监听本机端口，避免对外暴露非必要服务；并支持代理与加密设置以提升传输安全。
所有从外部（用户输入、种子元信息、对等节点）获得的数据均视为不可信，在用于界面展示与本地处理前做必要的格式校验；界面使用普通文本渲染，不做 HTML 解释，防止注入。

八、权限说明
本软件仅在首次使用（或系统要求）时申请实现核心功能所必需的权限：
（1）网络访问：BitTorrent 对等传输所必需的联网通信；
（2）后台运行：允许切换到后台后继续执行下载；
（3）网络状态信息：用于检测当前为 WiFi 或移动数据，避免在非预期网络下自动下载；
（4）WiFi 信息：读取当前连接的 WiFi SSID，以实现“仅允许白名单 WiFi 传输”，该信息仅在设备本地处理，不上传。
